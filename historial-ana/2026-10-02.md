# ANA — 2026-10-02 — Worker PDF en producción

El reglamento de parque no se veía: el worker de PDF.js (`.mjs`)
llegaba como `application/octet-stream` y el navegador lo bloqueaba.

Los tipos MIME extra de `.mjs` en nginx se revirtieron.

En el build se copia `pdf.worker.min.js` a `dist/` y en producción se
carga con un blob `application/javascript`, sin depender del MIME del
servidor. Hay que volver a publicar la imagen del front.

# ANA — 2026-10-02 — Admin entra como vendedor

En Usuarios, el administrador puede entrar como el vendedor activo que
elija. La sesión de admin se guarda y se renueva al volver (el access
del admin suele vencer antes que el del vendedor). “Volver a admin”
y “Regresar a administrador” restauran esa sesión.

# ANA — 2026-10-02 — Estatus pendiente de validación en Odoo

El expediente y la conciliación no tenían `PENDING_VALIDATION` en la
selección de estatus VD, así que la venta firmada sin cotización/venta
en Odoo no mostraba “Pendiente de validación”. Ya está en etiquetas,
filtros y barra de estatus. Hay que actualizar el módulo
`sale_order_reception` en Odoo.

# ANA — 2026-10-03 — URL de firma en producción

El correo salía con `localhost:5173` porque el API no tenía URL del
front. Ahora el vendedor manda `window.location.origin` al enviar el
enlace. Hay que publicar front y backend.

# ANA — 2026-10-03 — Filtros y borradores vencidos

En Mis ventas, el filtro de fechas usa alta o última actualización, la
búsqueda también acepta folio, y las etapas sin coincidencias se ocultan.

Un borrador pasa del tiempo por default (desde que se creó, no desde el
último guardado) y deja de mostrarse. El API lo borra al listar.

# ANA — 2026-10-03 — Por corregir

En Mesa de Control (expediente y conciliación) el botón **Corrección de
datos** abre el expediente por secciones. Al mandar a corregir, la venta
queda en **Por corregir** (gris). El vendedor abre el lápiz y corrige
solo esos datos o documentos, agrupados igual.

Hay que actualizar `sale_order_reception` (2.13), publicar front y
backend, y en producción:

`ALTER TABLE sales ADD COLUMN IF NOT EXISTS correction_request text NOT NULL DEFAULT '';`

# ANA — 2026-10-03 — Formato del modal por corregir

Los campos usan el mismo control que la captura: sucursal, origen, sexo,
teléfono de 10 dígitos, fechas y el archivo como botón. Al cambiar
sucursal, tipo de servicio o parentesco también se guarda el id.

# ANA — 2026-10-05 — Enlace de firma en producción

El 400 “falta la URL del front” salía cuando el API no recibía
`frontUrl` en el body. Ahora también usa el origen de la página
(`Origin` o `Referer`). Nginx reenvía esas cabeceras al API.
Hay que publicar front y backend.

# ANA — 2026-10-05 — Bitácora con la acción real

El título ya no dice “Modificó venta” para todo. El correo de firma dice
que se envió el correo y de qué venta. El pago dice que se generó el pago.
La venta nueva muestra sus datos. Un cambio muestra solo el dato anterior
y el nuevo.
